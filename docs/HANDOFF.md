## 1. New Computer Setup & Portability Checklist

### 1.1 System Prerequisites
1. **macOS 14.0+ (Sonoma or newer)** with Xcode / Command Line Tools providing **Swift 6.0+** (`swift --version`).
2. **Tesseract & Leptonica C Libraries** (linked by the `CTesseract` target in [`Package.swift`](../Package.swift) via `/opt/homebrew/lib` on Apple Silicon or `/usr/local/lib` on Intel):
   ```bash
   brew install tesseract leptonica
   # Optional: historical & polyglot language packs (Ancient Greek, Fraktur, Latin)
   brew install tesseract-lang
   ```

### 1.2 Sanity Verification on Arrival
Run from the repository root:
```bash
swift build
swift test
```
All test suites under [`Tests/`](../Tests) synthesize their own PDFs and bitmaps at runtime and have **zero external file dependencies** (currently **164 tests across 26 suites**, 4 of them the skipped opt-in corpus tests, passing with 0 warnings). The one exception is the opt-in real-book suite [`RealCorpusTests`](../Tests/ScanTailorAppleBackendTests/RealCorpusTests.swift), skipped unless `SCANTAILOR_CORPUS_DIR` is set (see §1.3).

### 1.3 Notes on Git-Ignored & External Items
- **Git Remote**: Check `git remote -v`. If no remote is configured when migrating, either push `main` to a new remote (`git remote add origin <url> && git push -u origin main`) or transfer via `git bundle create scantailor.bundle --all`.
- **`.agents/` & `.claude/` (Git-Ignored)**: Listed in [`.gitignore`](../.gitignore). `.agents/` holds optional local agent skills (`swift-expert`, `skill-creator`) and `.claude/skills/` holds the Claude Code copy of `swift-expert`; neither is required to build, test, or develop. Copy them manually when migrating machines.
- **Empirical Benchmark PDFs (External / Cloud-Synced)**: [`docs/WHITE_PAPER.md`](WHITE_PAPER.md) references three real-world test PDFs stored outside the repo in `OneDrive-MRC/PDFs-in-the-making/`:
  - `flannery.1993` (*Flannery 1993* — clean calibrated scan)
  - `vermeersch.1934` (*Vermeersch 1934* — photocopied two-page spreads with dark gutter seams)
  - `simpson.1968/simpson.1968.400-403.pdf` (*Simpson 1968* — handheld smartphone camera spread wrapped at 72 DPI)
  These files are **not** needed for `swift test`, only for optional empirical CLI runs and Phase 7.1 benchmark verification.
- **Running the tests (use release)**: the image loops run about 80× slower unoptimized, so a debug `swift test` takes about 10 minutes (the real-book tests about 30). Use [`scripts/test.sh`](../scripts/test.sh): `fast [filter]` runs the whole suite in release (`-c release -Xswiftc -enable-testing`, about 1 minute including the build, 5–10 s of test time), `corpus [filter]` does the same with `SCANTAILOR_CORPUS_DIR` set (default: the OneDrive library below), and `debug [filter]` runs the debug suite. Release compiles out the `assert` bounds checks in the `BinaryBitmap`/`GrayscaleBuffer` subscripts, so **run `scripts/test.sh debug` once per substep, in the background, before committing**. Build the CLI with the same flags (`swift build -c release -Xswiftc -enable-testing`) so tests and CLI runs share one build.
- **Opt-in real-book tests (Substeps 6.1.2, 6.2.1)**: `RealCorpusTests` reads short excerpts straight from the library (no scans are copied into the repo): `flannery.1993` pp. 1–8, `gury.1866` pp. 300–307, `vermeersch.1934` pp. 1–6, `long.2015` spreads 57–59 (folios 110–115), `SLE.2` scans 2–8 (landscape table on scan 5) and `pilsner.2006` pp. 1–6 (thumbnail cover). Point `SCANTAILOR_CORPUS_DIR` at the folder that holds the book folders and run them **in release** (about 20 s each):
  ```bash
  scripts/test.sh corpus RealCorpusTests
  ```
  Real scans are in `<book>/00-pdf-orig/` (occasionally `00-jpeg-orig`). `scantailor-cli process … --diagnostics-dir <dir>` writes `<stem>-lines.json` there (every page's detected text lines, anchor and registration) for debugging detector misses.

### 2.1 Strict 5-Layer Swift 6 Package Structure
Every target compiles with `.swiftLanguageMode(.v6)` and `.enableUpcomingFeature("StrictConcurrency")`. **Apple-specific frameworks (`PDFKit`, `CoreGraphics`, `Vision`, `Metal`, `Accelerate`) never leak into `ScanTailorContracts`, `ScanTailorCore`, or `ScanTailorPipeline`.**

| [`ScanTailorPipeline`](../Sources/ScanTailorPipeline) | 3-pass [`BookPipelineCoordinator`](../Sources/ScanTailorPipeline/BookPipelineCoordinator.swift) (pre-raster font-scale calibration; Pass 1: perspective rectification + 600 DPI per-page analysis; Pass 2: book-wide statistical harmonization & IQR outlier filtering; Pass 3: 600 -> 300 DPI render, OCR, post-calibration typography telemetry, & PDF assembly), `BookProcessingManifest` (incl. per-source-page `SourcePageGeometryRecord`s), and polyglot [`DualOCREngine`](../Sources/ScanTailorPipeline/OCR/DualOCREngine.swift). |

### 3.5 Recently Completed: Substep 4.2.2 (`Dual-Pass Illumination Flattening & Anti-Starvation`)
Implemented dual-pass background quotient flattening and multiplicative anti-starvation contrast leveling in [`Sources/ScanTailorCore/Binarization/BackgroundNormalizer.swift`](../Sources/ScanTailorCore/Binarization/BackgroundNormalizer.swift), plus outlier-robust Wolf-Jolion anchors in [`AdaptiveBinarizer.swift`](../Sources/ScanTailorCore/Binarization/AdaptiveBinarizer.swift):
1. **Configuration & Telemetry** (backward-compatible `decodeIfPresent`): `enableDualPassFlattening` (`true`), `secondPassBlurSigmaScale` (`0.65`), `enableAntiStarvationContrastLeveling` (`true`), `maximumContrastGain` (`2.50`, `[1.0, 3.5]`); `DerivedKernelParameters` gains `dualPassApplied`, `secondPassDownsampledBlurSigma`, `contrastLevelingApplied`, `peakContrastGain`.
2. **Pass 1 → Pass 2 residual background**: unclipped `UInt16` quotient $Q_1 = 255 \cdot I / B_1$; a **mode-seeking per-block crest** (two successive trimmed upper means, `q1 >= 15/16 * current`) closed by slope-aware `closeSlopeAwareUInt16`; pure-paper sampling at $Q_1 \ge 0.88 \cdot \text{crest}$ with **PSF-skirt rejection** (candidates below $0.96 \cdot \text{crest}$ that touch a foreground pixel, $Q_1 \le 0.78 \cdot \text{crest}$, are discarded); multi-stride diffusion inpainting; and normalized Gaussian smoothing with **point-reflected boundaries** (`SmoothingBoundary.linearExtrapolate`, $v(-k) = 2v(0) - v(k)$), which reproduces linear edge ramps exactly. $B_{\text{eff}} = B_1 \cdot B_2 / 255$ in Q6 fixed point.
3. **Anti-starvation contrast leveling**: the ink-core absorption envelope is sampled only from paper-supported cells, rejecting outliers above `p90 + 40` (desk strips / black borders). The crisp reference is `clamp(p90, 145, 175)` and the gain is $g = \text{target}/\text{env}$, applied **multiplicatively** ($A' = A \cdot (1 + (g-1)\,w)$, because veiling glare compresses absorption multiplicatively). The smoothstep gate $w$ (absorption 16 → 40) is driven by the **3×3 peak absorption**, so stroke-edge pixels inherit their stroke's gain (uniform stroke weight) while isolated grain and bleed-through (absorption ≤ 16) stay untouched.
4. **Root causes fixed while closing the last 3 tests**:
   - *Spine gutter cloud (1476 → 0 false positives at `x = 4..6`)*: the Pass 2 clamp-to-edge Gaussian over-estimated the steep spine ramp in the outermost cells, so normalized paper there was only 185–215. The point-reflected boundary fixes this.
   - *Stroke-weight non-uniformity (Wolf-Jolion 7 px upper vs 9 px lower → 9/9; Sauvola 7/7)*: three compounding causes. (a) The affine boost `16 + g·(A − 16)` under-boosted 25 %-coverage PSF skirts. (b) The x < 22 desk strip read as "ink" at absorption ≈ 238 and inflated the envelope. (c) Faint veiled skirts (0.92 × paper) passed the 0.88 paper gate and biased $B_{\text{eff}}$ 1.9 % low in veiled text rows (now +0.05 %), which the gain then amplified.
   - *Dense columns*: the old fixture left clean 4×4 blocks above short glyphs (Pass 1 MAE 0.14, so there was nothing to recover). The fixture now sets uniform 24-px bodies solid through a realistic 3×3 binomial PSF (85 % ink absorption): MAE₁ = 9.07, MAE₂ = 0.27. Under that realistic PSF the previous crest/paper gate made Pass 2 *worse* than Pass 1, which the mode-seeking crest and skirt rejection fix.

### 3.6 Recently Completed: Substep 5.1.1 (`DocumentQuadDetector` — Paper Edge & Contrast Boundary Detection)
A standalone 4-corner document quadrangle estimator in [`Sources/ScanTailorCore/Geometry/DocumentQuadDetector.swift`](../Sources/ScanTailorCore/Geometry/DocumentQuadDetector.swift), with pure-Swift kernels in [`QuadDetectionKernels.swift`](../Sources/ScanTailorCore/Geometry/QuadDetectionKernels.swift). It is wired into `BookPipelineCoordinator` and the manifest by Substep 5.1.2 (§3.7).
1. **Public API** (`Sendable`, `Equatable`, `Codable`, with `decodeIfPresent` defaults):
   - `DocumentQuad`: TL/TR/BR/BL corners in continuous source pixels, plus `corners`, `area`, `boundingBox`, `contains(_:)` and `fullFrame(width:height:)`.

2. **Algorithm**:
   - Integer area-average to a working raster with a long side of at most 1024 px.
   - Paper region: score `localMean − localStd`, Otsu split (with a second split of the bright class when dark text would otherwise group a light desk with the paper), closing, dominant components, hole fill, convex hull, then the maximum-area inscribed quad.

A frame-filling region counts as `fullFrame` only if the 1–3 % border ring is raw paper-class (≥ 80 %); otherwise it is rejected, which is how a wood-only image is rejected.
3. **Accuracy on synthetic fixtures** (1800×1350, 3×3 PSF, noise σ = 3): corner errors ≤ 0.07 px for the wood desk, low-contrast laminate (contrast 35, confidence 0.90), thumb occlusion of the left side and bottom-left corner, the bent open-book spread, and the 0.5× rescale.

### 3.8 Recently Completed: Substep 5.2.1 (Pre-Binarization Table Surface Masking)
Release Criterion 1 is now met for residual desk after rectification and for pages where rectification found no usable quad: both are filled with a paper-toned estimate before `BackgroundNormalizer`/`AdaptiveBinarizer` ever see them.
1. **`PaperRegionMasker`** ([`Sources/ScanTailorCore/Binarization/PaperRegionMasker.swift`](../Sources/ScanTailorCore/Binarization/PaperRegionMasker.swift)):
   - Classifies paper vs. desk the same way `DocumentQuadDetector` does (`localMean − localStd`, Otsu, second split for a light desk with dark text), then **flood-fills only the non-paper pixels connected to the image border** — interior dark content (ink, illustrations) that never reaches the edge is never touched.
   - **Trust gate before anything is masked**: local variance right at the candidate boundary must exceed the paper's own baseline variance a bit further out by `minimumBoundarySharpnessStd` (default `3.0`).    - **Mode**: `full` when the border-connected desk covers more than `residualModeAreaThreshold` (`0.25`) of the frame (no rectification, or a rejected/disabled detection) — masks the whole extent found, unless the "paper" class's own convex hull also spans nearly the whole frame with no clean border ring (bare wood grain with no document at all, mirroring `DocumentQuadDetector`'s frame-filling check), in which case nothing is masked. `residual` otherwise (the normal post-rectification case) — masking is restricted to within `residualDepthFraction` (`0.08`) of each edge and capped at `residualAreaCap` (`0.15`) of total area; exceeding the cap skips masking entirely and flags the page, so a misclassification can only leave visible desk for 5.2.2 to clean up, never erase content.

### 3.9 Recently Completed: Substep 5.2.2 (Macro-Cluster Border Cleaning Fallback)
Closes Phase 5. Desk that survives rectification and masking in a way the standard border rules cannot see is now excised, but only on pages whose own geometry telemetry says confidence was marginal.
1. **The gap**: `BorderAndSpeckleCleaner.removeScanBorders` erases multi-edge components and edge bars up to 2× the 14 % strip limit, but (G1) desk *detached* from the frame edge by a white band (the `capped:depth` paint band, deskew's white corner fill) is never near an edge, and (G2) single-edge blocks deeper than that limit or shorter than 20 % of the side are kept.
2. **Algorithm** ([`MacroBorderFallback.swift`](../Sources/ScanTailorCore/Binarization/MacroBorderFallback.swift), `BorderAndSpeckleCleaner.removeMacroBorderBlocks`): coarse grid (cell = short side / 64); a cell is dark at black density ≥ `0.30`. Per eligible side and per grid line, scan inward: leading cells must be empty (≤ 5 %) for at most 10 % of the page (bridges the paint band), then a solid run of dark cells (solidity ≥ 0.85, at most one missed cell). Contiguous lines form a candidate, accepted only if deeper than the standard strip limit, ≤ 35 % deep (`tooDeep`), ≥ 15 % of the edge (`shortSpan`), solid (`notSolid`), and **not text-like**: the fraction of blank pixel rows in the candidate must be ≤ 0.15 (`textLike`; text has line gaps, binarized grain or solid blocks have none). Excision erases black pixels in the candidate rectangle, then components lying wholly inside a 1-cell ring around it.
   - **Design finding**: the 0.30 threshold exists because binarized wood grain is a *noisy ~40 % black*, not solid. Density alone, and micro-block emptiness, cannot tell that from dense text (the binarized noise is spatially correlated); the blank-row test on whole candidates is what does. A flat synthetic block even binarizes to an outline only, so fixtures must be textured.
3. **Gating** (`SourcePageGeometryRecord.borderFallbackContext`): engages only on triggers `quad:rejected` (unless a full-mode mask handled it), `quad:marginal` (confidence < `borderFallbackMarginalConfidence`, default `0.70`), `quad:occluded:*`, `quad:cornerFallback:*`, `quad:lowContrastDesk`, `mask:capped:depth|coverage`, `mask:skipped:noSharpBoundary|noPaper`, or a `forced` override. Confident pages and flatbed scans pass through byte-identical. The gutter side of a `leftVerso`/`rightRecto` slice is never eligible.
4. **API**: `clean(_:fallback:) -> (bitmap, MacroBorderResult?)`; `clean(_:)` is unchanged. `BorderAndSpeckleCleaner.Configuration.macroBorder` (`MacroBorderConfiguration`, clamped; config decoder uses `decodeIfPresent`).
5. **Manifest/CLI**: `PageProcessingRecord.borderFallback: MacroBorderResult?` (`triggers`, `excisedFraction`, `excisedDepthBySide`, `rejectedCandidates`; `nil` = not engaged). `PageManualOverride.borderFallback: BorderFallbackPolicy?` (`automatic`/`forced`/`disabled`). Coordinator `Configuration.enableBorderFallback` / `borderFallbackMarginalConfidence`; CLI `--no-border-fallback`; summary line `Border Fallback: N excised | N engaged, nothing found | N rejected`. For the post-dewarp cleaning the dewarped result is recorded.
6. **Tests**: [`MacroBorderFallbackTests.swift`](../Tests/ScanTailorCoreTests/MacroBorderFallbackTests.swift) (7): deep block and detached remnant excised with text untouched, wood-grain block excised, legitimate content survives (text near the edge, a dense narrow text column, short block, 45 %-deep figure, gutter side), passthrough and legacy config decoding, context builder triggers/sides/overrides, and pipeline integration (forced/disabled/flag, textured-desk binarization, JSON round trip, legacy manifest, CLI flag). `133/133` pass across 22 suites, 0 warnings.

### 3.10 Recently Completed: Substep 6.1.1 (Running Header & Top Baseline Detection)
Opens Phase 6. Every page now gets a **top anchor**: the running header's baseline when the page carries a recurring header, otherwise the first body baseline (release criterion 4). **Telemetry only — no pixels change**; 6.1.2 consumes the anchors.
1. **Why**: `ContentBoxDetector` already keeps header/folio clusters inside the content box but never labels them, and Tier 1 pages are aligned by content-box top. A page without a header, or with a header at a different distance, therefore jumps.
2. **Per-page profile** ([`RunningHeaderDetector.swift`](../Sources/ScanTailorCore/Layout/RunningHeaderDetector.swift), `profilePage`): a word-popcount row ink profile over the content box (override box if set) splits text lines. Bands > 1.7× typical height are split at a near-empty row (≤ 20 % of peak) to separate touching lines; thin, wide, solid bands are **rules** folded into the line above (`hasRule`); accent-sized bands join the nearest line. Each line records bounds, **baseline** (first row below the ≥ 50 %-of-peak core), core height, and ink. Body pitch / core height are medians over lines *below* the top line. The top and bottom lines are split into ink segments at gaps ≥ 2.5 core heights for folio detection.
3. **Book clustering** (`analyzeBook`): per logical side (`verso`, `recto`, `single`). A top line is a **candidate** when the next baseline is ≥ 1.5 body pitches below it and its core height is 0.35–1.75× body core (taller = `titleLike`). Candidates are clustered mode-seeking on *(offset in pitches, height ratio)* with tolerances 0.35 pitch / 0.20; a cluster confirms running headers with ≥ 3 pages and ≥ 30 % of the side's text pages. Absolute page position is deliberately *not* used (camera captures shift it). Sides with < 3 text pages accept candidates at low confidence (`book:tooFewPages`).
4. **Folios**: in the header line, the outer-end segment (verso left, recto right, single either) no wider than 4.5 header core heights; a header line that is itself that narrow is a folio-only header. A footer folio is a single narrow segment ≥ 1.5 pitches below the last body line; it is never taken as body.
5. **Anchor** (`PageTopAnchor`): `kind` (`runningHeader` / `bodyBaseline` / `none`), `anchorY`, `headerBox`, `headerBaselineY`, `folioBox`, `footerFolioBox`, `firstBodyLineTopY`, `firstBodyBaselineY`, `confidence`, `flags` (`header:outOfCluster`, `header:sizeMismatch`, `titleLike`, `sinkage`, `book:tooFewPages`, `override:*`, `noText`). Medians of the pages themselves, so the typical page does not move. New y = line − (anchor − content top); x is never touched; no even-pixel snapping is needed because every registered baseline lands on the same canvas row.
4. **Who is registered**: `fullBody` pages and `edgeAnchoredPartial` pages pinned by their top edge (new `PageLayoutPlan.verticalAnchorEdge` = `top`/`bottom`/`natural`, recorded by the harmonizer, `decodeIfPresent`). **Preserved** (kept as placed): Tier 3, Tier 2 bottom/natural, `titleLike`, `sinkage`, blank. **Left on box-top** with a flag: no anchor, confidence < 0.5, `header:outOfCluster`/`sizeMismatch` (`registration:ambiguousTop`), anchor outside the box, page line pitch > 30 % off the book's (`registration:atypicalLines`), a body-anchored page on a side where no header was found while the other side has them (`registration:headersUndetectedOnSide` — likelier a missed header than a headerless page), or a shift over min(3 pitches, 12 % of frame height) (`registration:shiftTooLarge`). Headerless pages in a header book align their first body baseline to the **body line**, so body text does not jump. Shifts are clamped to the canvas (`registration:clamped`).
5. **Manifest/overrides/CLI**: `PageProcessingRecord.registration` (`method` header/bodyBaseline/preserved/boxTop/manual, `shiftPixels`, `anchorCanvasY`, `flags`) and `BookProcessingManifest.verticalRegistration` (mode, header/body line Y, counts, max shift, header and body baseline **spread before → after** — the jitter metric for criterion 4 / Phase 7.1), all `decodeIfPresent`. `PageManualOverride.verticalRegistration`: `automatic` / `anchor` (force: skips tier, confidence and shift checks) / `boxTop`; a manual `overrideDestinationOrigin` always wins (`manual`). CLI `--vertical-anchor auto|box-top` and `--no-running-headers` (no anchors, so no registration); `inspect` prints `Vertical Registration: N header · N body · N preserved · N box-top | header spread a→b px | body spread a→b px`. `process --diagnostics-dir` also writes `<stem>-lines.json`. Coordinator `Configuration.verticalRegistrationConfiguration`.
6. **Tests**: [`VerticalRegistrationTests.swift`](../Tests/ScanTailorCoreTests/VerticalRegistrationTests.swift) (12: header line, headerless page, headerless book, every eligibility/fallback reason, guards and clamp, overrides and box-top mode, coding, harmonizer edges, CLI, and a pipeline test that **re-profiles the rendered bitmaps** — header baselines within 1 px with registration, 4+ px jitter with box-top), [`RunningHeaderCalibrationTests.swift`](../Tests/ScanTailorCoreTests/RunningHeaderCalibrationTests.swift) (8, synthetic copies of the real failures; note that synthetic glyph rectangles must not line up from line to line, or they look like streaks), and the opt-in [`RealCorpusTests.swift`](../Tests/ScanTailorAppleBackendTests/RealCorpusTests.swift) (4). Results on the real samples: Flannery 6 header pages, spread 9→0 px; Gury 5 header pages, 12→0 (both sides detected); **Long folios 110–115: 6/6 headers, all Tier 1, header spread 3→0 px and rendered baselines identical, fore-edge texture gone**; Long spreads 56–60: 10/10 headers, 15→0 px; Vermeersch pp. 1–6: verso headers found, 2 pages registered.
7. **Known limitations / hand-offs**: (a) header-to-first-body distance varies by up to ~20 px on some pages even in clean scans (Flannery body spread 24→21 px), so registering on the header leaves body lines slightly off — measured, not fixed; (b) **Simpson 1968** (`simpson.1968.400-403.pdf`): camera spreads are not cropped or split properly (table and desk kept, canvas 6,798 px wide) — a Phase 5 problem, untouched; (c) **Vermeersch**: pages beside spine noise or with the header fused to a noise patch still miss headers, and short excerpts leave several pages in Tier 3; (d) the left-over noise patch beside folios (Long) is still rendered; (e) registration is vertical only — horizontal re-centering stays with 6.2.x; (f) the pipeline test takes about a minute in debug.

### 3.12 Recently Completed: Substep 6.2.1 (Consensus Dimension Clustering)
Groups the processed pages into **canonical** pages and **dimensional outliers** (covers, plates, foldouts, landscape tables). It decides and records; it does **not** change how outliers are drawn: that is 6.2.2. Output for a book with no outliers is unchanged.
1. **Classifier** ([`DimensionConsensus.swift`](../Sources/ScanTailorCore/Layout/DimensionConsensus.swift), pure statistics on sizes and boxes, no pixels). A page is an outlier when its width or height differs from the book median by more than max(`iqrMultiplier` (1.5) × IQR, `toleranceFraction` (8 %) × median): `oversize`/`undersize`; `orientation` (landscape page in a portrait book); `contentOverflow` (normal page size but a text block > 15 % beyond the 85th percentile of the book's); `manual`. 8 % because ordinary cropping varies by up to ~5 % (bouscaren) and covers by 9 % or more. Fewer than 5 pages: not applied (`note: tooFewPages`). If more than 25 % of pages differ, or the IQR itself exceeds 25 % of the median (a large second size group such as ELPost's 22-page appendix), sizes are not trusted (`ambiguous`, only content overflow and manual classes count). Also `scaleMismatch` (body line pitch > 20 % off the book's; flag only, Pennacchi p. 42), a `proposedCanvasSize` for each outlier (its page size, or its text block if larger) and `outlierGroups` (outliers within 5 % of one size).
2. **Split veto** (pre-pass-1, `splitMode == .automatic` only): when ≥ 75 % of the source scans are portrait, a landscape scan is processed as a single page, not split down the middle (SLE.2's tables). Recorded in `splitVetoedSourcePages`.
3. **Harmonizer** ([`MarginHarmonizer.swift`](../Sources/ScanTailorCore/Layout/MarginHarmonizer.swift)): `harmonizeBook(pages:detector:dimensionOutliers:outlierCanvasSizes:)`. Outliers are excluded from the median page size, the width prior and the canonical-frame percentiles; they skip pass-2 width trimming (their text block stays whole), are forced to Tier 3 and get `PageLayoutPlan.proposedCanvasSize` (non-nil = outlier, `isDimensionOutlier`). With fewer than 3 canonical pages the set is ignored. Placement on the shared canvas is unchanged Tier 3 placement, so **Flannery's cover is still clipped until 6.2.2 gives it its own page**.
4. **Registration**: outliers are Tier 3, hence preserved; their record gains `registration:dimensionalOutlier`.
5. **Manifest/overrides/CLI** (all optional in JSON): `PageProcessingRecord.dimension` (`dimensionClass`, `kinds`, signed `widthDeviation`/`heightDeviation`/`linePitchDeviation`, `scaleMismatch`, `proposedCanvasSize`, `groupIndex`), `BookProcessingManifest.dimensionConsensus` (applied, ambiguous, note, median size, counts, `outlierPages`, `outlierGroups`, `splitVetoedSourcePages`, tolerance). `PageManualOverride.dimensionClass` (`canonical`/`outlier`). CLI `--dimension-consensus auto|off` (off: old behaviour, no veto) and `--outlier-tolerance <0.02–0.5>`; `inspect` prints `Dimension Consensus: N canonical · N outlier (p1 oversize +30% W +9% H; …) | not split: scans 5`.
6. **Tests**: [`DimensionConsensusTests.swift`](../Tests/ScanTailorCoreTests/DimensionConsensusTests.swift) (14; 13 in milliseconds, one small pipeline run of ~2.5 s), plus `RealCorpusTests`: Flannery cover is the one oversize outlier and the canvas stays under 4,200 px; SLE.2 table kept whole and marked `orientation`; Pilsner thumbnail cover is `undersize`.
7. **Known limitations / hand-offs**: (a) outliers are only recorded, not rendered on their own canvas (**6.2.2**; `ApplePDFDocumentWriter` already takes a page box per page, but the coordinator renders every page on the shared canvas); (b) the canonical frame of a book whose body pages themselves vary is unchanged; (c) ELPost's second size group (pp. 336–357) is not an outlier (ambiguity guard) and is not recorded as a cluster; (d) scale mismatch is not corrected; (e) the veto looks at scan shape only, so a portrait foldout in a landscape-scan book is not caught; (f) the veto runs before rectification, on the declared scan size.

### 3.13 Recently Completed: Substep 6.2.2 (Independent Outlier Trim Box)
Each dimensional outlier is drawn on its **own canvas and PDF page size**; the book's shared canvas and canonical frame are untouched.

1. **Manual list first**: `--outlier-pages 1,45,89-91,120 | none` (1-based *output* pages) → `DimensionConsensus.Configuration.manualOutlierPages` (0-based). It replaces detection entirely: works with detection off or fewer than 5 pages, beats per-page `dimensionClass`, `none` = no outliers, summary note `manualList`, numbers past the end are listed in `ignoredManualPages`. With a manual list the harmonizer needs only 1 canonical page (`minimumCanonicalPages`). Per-page `dimensionClass: outlier` now also works when automatic detection is off or the book is short (was ignored in 6.2.1).
2. **Rendering** (pass 3 of [`BookPipelineCoordinator.swift`](../Sources/ScanTailorPipeline/BookPipelineCoordinator.swift)): with `isolateOutlierCanvases` (default; `--outlier-canvas isolated|shared`, `shared` = 6.2.1 output) the plan's `canvasSize` becomes `proposedCanvasSize` (scan size, grown to hold the text block) and the content keeps its natural position, unless a manual `overrideDestinationOrigin` is set. `PageLayoutPlan.canvasSize` is now `var`. The PDF writer needed no change (it already takes a box per page).
3. **Anti-billboard cap**: the canonical canvas's clamp factor is computed once; outliers get the same factor (a cover keeps its size relative to the body) and are then capped on their own only if still billboard-sized. Outlier caps never touch `canonicalCanvasSize`/`clampedCanonicalInches`. Skipped when an explicit `--page-size`/`--content-box-size`/`--input-dpi` is given. Outliers are left out of the post-calibration glyph sample.
4. **Manifest** (all optional): `PageDimensionRecord.pdfPageSizePoints` (non-nil = own canvas), `DimensionConsensusSummary.isolatedCanvasPages`, `.ignoredManualPages`. CLI line shows `own 8.5×11.0 in`.
5. **Tests**: [`OutlierCanvasTests.swift`](../Tests/ScanTailorCoreTests/OutlierCanvasTests.swift) (7, ~2 s; uses a recording PDF writer), plus corpus assertions for Flannery (cover on its own canvas, whole), SLE.2 (landscape table page) and Pilsner (small cover page).
6. **Known limitations**: (a) the "outliers share the body's clamp factor" rule has no pipeline-level test (it needs billboard-sized pages); (b) thumbnail covers stay small (no upscaling of 1-bit images); (c) two-page viewers show odd-sized spreads around outliers; (d) foldouts are not rotated; (e) the manual list is by output page, so adding/removing pages or changing the split changes what the numbers mean.

### 3.14 Recently Completed: Substep 6.3.1 (Manifest-Driven Per-Page Adjustments)
The tool is a power tool for an iterate-and-inspect loop (default run → look → write a small edit file → re-run), not a system that foresees every edge case.

1. **Adjustments file** (`--apply-manifest <file>`; [`PageAdjustments.swift`](../Sources/ScanTailorPipeline/PageAdjustments.swift)): strict JSON, separate from the large machine-written manifest. Sections: `book` (ordinary CLI options by flag name, without `--`; booleans become flags; the command line still wins), `scans` (`split` single|spread|auto, `splitX` "52%"/length, `disableRectification`, `disableDeskMask`) and `pages` (`skew`, `disableDewarp`, `contentBox.rect` [l,t,r,b], `contentBox.nudge` {top,left,bottom,right} positive = right/down, `offset` {x,y}, `tier`, `outlier` true|false, `pageSize`, `keep`, `drop`, `runningHeader`, `verticalRegistration`, `borderFallback`). Lengths **require a unit** (in, mm, cm, pt, px = 600 DPI raster pixels). Keys starting with `_`, `note`, `comment` are ignored. **Every problem is collected and reported together before any scan is processed**, with "did you mean" suggestions (`AdjustmentsError`). A complete manifest from an earlier run given to `--apply-manifest` is recognized and applied the old way (read-only).
2. **Stable references** (`PageReference`): `45` = output page 45 of the run being looked at; `s12` = scan 12 of the source PDF, **counted from the start of the PDF even with `--page-range`** (new `BookProcessingManifest.sourceScanNumbers`; `scanNumber(of:)`, `scanReference(of:)`); `s12L`/`s12R` = left/right half. Specificity wins: `45` < `s12` < `s12L`. `--outlier-pages` accepts the same names (`1,45,s120L`) and still replaces automatic detection.
3. **Application** (pass 1 of [`BookPipelineCoordinator.swift`](../Sources/ScanTailorPipeline/BookPipelineCoordinator.swift); resolution in [`AdjustmentResolver.swift`](../Sources/ScanTailorPipeline/AdjustmentResolver.swift)): the file is overlaid on stored `manualOverride`s (file wins per field). New `PageManualOverride` fields: `contentBoxNudge` (resolved into `overrideContentBox` during pass 1, so stored records stay idempotent), `destinationOffset` (applied after every automatic placement), `forcedTier` (`MarginHarmonizer.harmonizeBook(forcedTiers:)`), `pageSizeInches` (outlier on its own canvas, same aspect ±5 %), `keep`, `drop` (page leaves the book, recorded in `prunedPages`). Scan edits: forced `split`/exact `splitX` cut (a straight vertical `GutterSplitLine`), geometry overrides via the existing `SourcePageGeometryOverride`.
4. **Reporting**: `BookProcessingManifest.adjustments` (`AdjustmentReport`: `applied` entries with field names, `ignored` entries with the reason, e.g. "scan 6 was not split into two pages", "scan 99 was not processed", "no output page 99"). Printed after the run and by `inspect`. Unresolved outlier scan names go to `DimensionConsensusSummary.ignoredManualReferences`.
5. **Cheap stage runs**: `--stop-after layout` (`PipelineStop`, `DiscardingPDFWriter`) runs pass 1, consensus, harmonization and registration, then renders, recognizes and writes nothing (needs `--manifest` or `--diagnostics-dir`; `-o` optional). It writes **layout contact sheets** ([`LayoutContactSheetRenderer.swift`](../Sources/ScanTailorAppleBackend/LayoutContactSheetRenderer.swift); `layout-sheet-NN.png`, ~40 DPI, facing pages touching; red = canonical frame, green = text block as placed, orange = outlier on its own canvas, blue label = low confidence; also `--layout-sheets` on a full run). **Measured on Flannery pp. 1–8: a stopped run took about as long as a full run (13 s vs 11–14 s)**: pass 1 dominates, so the real speed-up is 6.3.2 (caching); the stop is still useful because it needs no output PDF and is the quickest way to get the manifest and sheets.
6. **`inspect`**: `inspect <manifest> --pages` prints one row per page (scan name, side, tier, page and text size, **margins L/T/R/B in inches**, skew, confidence, notes) plus the **margin spread of full-body pages per side** (the number to drive toward zero) and the list of own-canvas and low-confidence pages; `--json` gives the same rows (`PageRow`) for programs. (`--stop-after scan` from the plan was dropped: pass 2 costs almost nothing, so it would have saved nothing.)
7. **Tests**: [`AdjustmentsTests.swift`](../Tests/ScanTailorCoreTests/AdjustmentsTests.swift) (15 tests, ~2 s: parsing and error reporting, nudge idempotency, offset, tier, drop, scan split, outlier scan names, page size, stop-after equals full-run plans, manifest coding, CLI loading) and a corpus test (SLE.2 scans 2–8: absolute scan numbers under `--page-range`, stopped run).
8. **Known limitations**: (a) plain page numbers shift when blank pruning or `drop` changes the numbering: prefer scan names; (b) `pageSize` only rescales an outlier's PDF page (same aspect), it does not reflow; (c) no manual quadrangle in the file (use a full manifest's `sourcePageGeometry[].manualOverride`); (d) stopped runs still pay for pass 1 (6.3.2); (e) the contact sheet draws the cleaned bitmap cropped to the text block, not the exact rendered cluster mask; (f) margins in `inspect` are computed from the plan on the processing canvas (before any anti-billboard scaling); (g) a stored manifest's overrides are keyed by output page number, so an old manifest re-run after the numbering changed applies them to the wrong page (pre-existing).

### 3.15 Recently Completed: Substep 6.3.2 (Cached and Parallel Re-Runs)
Goal: an agent iterating with `--apply-manifest` / `--stop-after layout` should not pay for pass 1 on every iteration.

1. **Measured first** (Flannery 1993, 16 scans, before the change): 26.8 s, of which pass 1 19.2 s (binarizing alone 13.9 s, i.e. `BackgroundNormalizer`), OCR 4.0 s, pass 2, render and PDF writing well under 1 s together. Nothing ran in parallel; peak memory 8 GB.
2. **Pass-1 cache** ([`ScanProcessing.swift`](../Sources/ScanTailorPipeline/ScanProcessing.swift), [`PipelineCache.swift`](../Sources/ScanTailorPipeline/PipelineCache.swift)): per scan a `ScanHeader` (geometry record, split decision, sides) and per page a `SliceOutcome` (cleaned bitmap, skew, dewarp telemetry, traced lines, border fallback, automatic detection, ink density, blank verdict). Keys are SHA-256 of: code version, every pass-1 setting (`pass1Fingerprint`: binarizer, cleaner, detector, rectifier, masker, font-scale config, DPIs, dewarp, pruning, page size, accelerator type, OCR identity and languages), the scan's identity (PDF content hash + scan index + render DPI, or the pixels for buffer input), the scan-level edits (split mode after veto, `splitX`, geometry override) and, per page, the pixel-changing edits (`HeavyPageEdits`: skew, disableDewarp, borderFallback). Entries are binary plists, LZFSE-compressed (~275 KB per page), written to a temp file and renamed; any unreadable entry is a miss. Content-box rect/nudge, tier, offset, outlier, page size, keep/drop and all book options are applied after the cache, so they cost only the cheap passes. A cache hit does not even rasterize the scan.
3. **OCR cache** (`CachedOCR`): keyed by the rendered output bitmap, `OCREngine.cacheIdentity` (new protocol requirement with a `String(reflecting:)` default; Tesseract sorts its `variables` and adds library versions, Vision adds the OS version, Dual combines both) and languages. Every page is re-rendered and the PDF rewritten each run (cheap); only pages whose pixels changed are recognized again.
4. **Parallelism** ([`BoundedParallel.swift`](../Sources/ScanTailorPipeline/BoundedParallel.swift)): pass 1 runs scans and pass 3 renders and recognizes pages at most `jobs` at a time, results in input order. Scans are loaded one at a time by their job (sizes for the landscape split veto come from the page boxes, computed exactly as the reader does). Output numbers, `.single` book sides, drops and blank pruning are assigned afterwards in scan order; page edits are matched speculatively by scan name only, and a page whose final pixel-changing edits differ (an edit by plain page number, or a stored manifest's override) is processed again; such a page has an override, so it is never pruned and the numbering stands. Even one job runs in a child task: memory that Metal/CoreGraphics release only when a task ends was what made the old serial run peak at 8 GB.
5. **Run report** (`BookProcessingManifest.run`, `PipelineRunReport`): jobs, cache counts, elapsed time per pass and work time per stage summed over jobs. It changes every run; leave it out when comparing manifests.
6. **CLI**: `-j/--jobs <n>` (default 4), `--cache-dir <dir>` (default `~/Library/Caches/ScanTailorReborn`), `--no-cache`, `--timings`. The code version is the executable's Mach-O `LC_UUID` (`ScanTailorCLI.buildIdentity()`), so a rebuilt binary never reuses older results; the source identity is a SHA-256 of the PDF (about 0.3 s per 500 MB). One line per run: `Cache: 15/16 scans reused, OCR of 3/16 pages reused (...)`. Progress now reads "Processed scan n/total".
7. **Results** (Flannery 1993, 16 scans, release build, 8P+2E cores, 32 GB):

   | Run | Wall | Peak memory |
   |---|---|---|
   | before 6.3.2 (serial, everything in memory) | 26.8 s | 8.1 GB |
   | `--jobs 1 --no-cache` | 27.4 s | 1.45 GB |
   | `--jobs 2` / `4` / `8`, cold | 16.0 / 12.5 / 10.9 s | 2.2 / 4.2 / 5.4 GB |
   | warm, nothing changed (full PDF) | 0.65 s | 0.19 GB |
   | warm, `--stop-after layout` | 0.39 s | 0.16 GB |
   | warm, skew on one scan + offset on one page | 6.4 s (one scan recomputed; 13 pages re-OCR'd because the book-wide frame moved) | — |
   | warm, skew by page number | 2.8 s (`--stop-after layout`, one scan) | — |

   Cold, warm and serial runs give identical manifests (without `run`) and identical PDF content (only creation date and file ID differ). OCR (Apple Vision) gains little from parallelism (5.2 → 4.5 s).
8. **Tests**: [`PipelineCacheTests.swift`](../Tests/ScanTailorCoreTests/PipelineCacheTests.swift) (9 tests, ~2 s: warm = cold with zero OCR calls; parallel = serial with splits, drops and page-number edits; one pixel edit re-processes one scan, layout edits none; page-number edits cached after correction; new code version / changed option reuses nothing; corrupt and missing entries recomputed; a stopped run fills the cache; `BoundedParallel` order, limit, progress, errors; CLI flags and formatting) and a corpus test (SLE.2 scans 2–8: four jobs, cold and warm cache equal the serial run; the landscape veto still found from page boxes).
9. **Known limitations**: (a) a content-box or skew change on one page usually moves the book-wide frame, so most pages' pixels change and their OCR runs again (OCR keyed by the placed text block instead of the page would avoid it); (b) the cache is never pruned: delete the directory (safe at any time); about 275 KB per page plus OCR; (c) every rebuild invalidates everything (by design: no stale results); (d) `PipelineOutput` still holds every cleaned 600 DPI bitmap (about 4 MB per page at 600 DPI, i.e. ~2 GB for 500 pages); (e) binarizing (`BackgroundNormalizer`, ~0.9 s per page) is untouched and remains the cold-run cost; (f) a stored manifest's overrides keyed by output number (pre-existing, §3.14 g) also drive re-processing.
